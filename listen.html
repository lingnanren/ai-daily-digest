中文摘要

当一个 Apartment（Windows UI 自动化中的一个概念）关闭时，其在 CoreApplication Properties 中的条目通常不会被立即删除，除非它是最后一个活动的 Apartment。这意味着即使 Apartment 已经关闭，其属性信息仍可能保留在内存中，直到系统清理或最后一个 Apartment 关闭。这种行为对于理解和调试 Windows 应用的生命周期管理至关重要。

English Summary

When a source Apartment in Windows shuts down, its entries in CoreApplication Properties are generally not immediately removed unless it's the last active Apartment. This means property information can persist in memory even after the Apartment is gone, until system cleanup or the final Apartment closes. This behavior is crucial for understanding and debugging the lifecycle management of Windows applications.

13. 废除锁中毒

Abolish Lock Poisoning — lucumr.pocoo.org · 7 小时前 · ⭐ 23/30

中文摘要

Rust语言中的“锁中毒”（mutex poisoning）特性被认为是一个不合时宜的设计。当一个互斥锁（Mutex）在持有期间发生恐慌（panic）时，该锁会被标记为中毒状态，后续的锁定操作将返回错误。作者认为，如果Rust语言今天才引入此特性，可能不会被接受，并讨论了其动机和潜在问题。

English Summary

The 'mutex poisoning' feature in Rust is described as an anachronistic design. When a std::sync::Mutex panics while held, it becomes poisoned, causing subsequent lock() calls to return a PoisonError. The author argues this feature likely wouldn't be adopted if introduced today and discusses its rationale and drawbacks.

🏷️ Rust, mutex, concurrency, poisoning
